# Claude Code vs Codex 使い分けガイド

2026-06-11 に実施した比較テスト（PR #21・#22 ほか計4テスト）の結果をもとにした、
2つのAIコーディングエージェントの使い分けメモです。

## テストで確認できたこと

| テスト | 内容 | Codex の結果 |
| --- | --- | --- |
| ① | リポジトリ構造の把握・ファイル読解 | ⭕ 完璧 |
| ② | README編集 → PR作成 → マージ（PR #21） | ⭕ 完璧 |
| ③ | `debug/` ログ確認・自己能力レポート | ⭕ 完璧 |
| ④ | index.html に新機能追加 → PR（PR #22） | 🔺 コードは◎、実ブラウザ確認だけ不可 |

PR #22 は Claude Code 側でも独立検証済み（`node scripts/check.mjs` すべてOK・
index.html のみ +30/-5・IndexedDB への影響ゼロ）。

## 使い分け表

| 観点 | **Codex**（自分のPCでローカル実行） | **Claude Code**（クラウドで実行） |
| --- | --- | --- |
| コード編集・PR作成 | ⭕ 得意 | ⭕ 得意 |
| 実ブラウザでの目視確認 | ❌ Browser機能が `file://`/`localhost` をブロック → モックテストで代替 | ❌ クラウドのため実画面は見られない |
| git push の認証 | 🔺 GCM の OAuth 画面が出ることがある（人の操作が必要） | ⭕ クラウド側で完結・画面は出ない |
| 自分のPC内のファイル操作 | ⭕ ローカルに直接触れる | ❌ クラウドの隔離環境のみ |
| 長時間・大規模な調査/リファクタ | 🔺 ローカル資源に依存 | ⭕ クラウドで腰を据えて作業しやすい |
| 並行作業・PR監視 | 1セッション中心 | ⭕ サブエージェント並列・PRイベント監視が得意 |

## 結論（ざっくり）

- **自分のPCの中身を直接いじってほしい・手元で動かしたい → Codex**
- **クラウドで完結させたい・認証画面を出したくない・大きめの調査やPR監視 → Claude Code**
- **共通の弱点**: どちらも「実際の画面を目で見る」確認は苦手。
  → 最終目視はオーナー（人間）が担当するのがベスト。
